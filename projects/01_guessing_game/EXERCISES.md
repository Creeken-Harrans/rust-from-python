# 猜数字游戏 (Guessing Game) — 练习指南

## 项目概述

你已经阅读了 `README.md` 和 `src/main.rs`，了解了这个经典命令行猜数字游戏的完整实现。请在不直接复制粘贴的前提下，通过以下分层练习加深对 Rust 核心概念的理解。

---

## Level 1: 基础练习（理解现有代码）

### L1-1: 运行与观察

1. 使用 `cargo run` 运行游戏，完整玩一局（猜中数字）。观察调试模式下的 `[调试] 秘密数字是: ...` 输出。
2. 使用 `cargo run --release` 再次运行。Release 模式下的行为有何不同？为什么？
3. 运行 `cargo test`，观察哪些测试通过。阅读 `tests/integration_test.rs` 理解集成测试的结构。

**学习点**: `#[cfg(debug_assertions)]` 条件编译、`--release` 优化模式。

### L1-2: 修改数字范围

当前游戏生成 1-100 的随机数。修改代码使范围为 1-50。需要改哪些地方？有哪些地方容易遗漏？

**提示**: 检查 `generate_secret()`、范围验证 `if !(1..=100).contains(&guess)`、游戏说明文字 `print_welcome()`。

**学习点**: 代码一致性维护，魔术数字（magic number）的坏味道。

### L1-3: 修改提示语

把"太大了"和"太小了"的提示分别改为 "偏高啦" 和 "偏低啦"。注意提示语在 `game_loop()` 和可能的其他位置（如 hints）。尝试为新提示语撰写单元测试。

**学习点**: 字符串文本的集中管理，UI 与逻辑分离。

### L1-4: 解析更多错误输入类型

当前 `parse_guess()` 使用 `trimmed.parse::<u32>()` 解析输入。在 `src/main.rs` 末尾的 `#[cfg(test)]` 模块中添加以下测试用例：

- 输入 `"abc"` → 应为 `Err`
- 输入 `"12.5"` → 应为 `Err`（浮点数不可解析为 `u32`）
- 输入 `" 42 "` → 应为 `Ok(42)`
- 输入 `"99999999999999999999"` → 应为 `Err`（超过 `u32::MAX`）
- 输入 `"-5"` → 应为 `Err`（负数不可解析为 `u32`）

运行 `cargo test` 验证。

**学习点**: 边界测试、`parse::<T>()` 的限制、turbofish 语法。

### L1-5: 理解所有权流转

在 `game_loop()` 中，找出 `input` 变量的以下时刻：
- `input` 何时获得所有权（从 `read_input()` 返回）
- `input` 何时被借用（传给 `parse_guess(&input)`）
- `input` 何时被释放（Drop）

画出所有权流转图，并用注释标注每个阶段。

**学习点**: 所有权规则、`&str` vs `String`、移动语义。

## Level 2: 功能扩展（编写新代码）

### L2-1: 添加"困难度选择"

在游戏开始前让用户选择难度：

```
请选择难度（1: 简单 1-50, 2: 中等 1-100, 3: 困难 1-200）:
```

实现要点：
- 读取用户输入并解析为整数
- 根据选择调整 `generate_secret()` 的范围参数
- 使用 `match` 处理无效选择（输入 4 或 "abc"）
- 游戏说明文字动态反映所选范围
- **提示**: `generate_secret()` 当前不接受参数。如何优雅地扩展签名？`fn generate_secret(max: u32) -> u32` 是否更好？

**学习点**: 函数参数设计、`match` 穷尽性、用户交互流程。

### L2-2: 实现"重玩"功能

猜对后询问：

```
是否再来一局？(y/n):
```

- 输入 `y` → 重新开始一局（新的秘密数字，清零尝试次数）
- 输入 `n` → 退出程序
- 其他输入 → 提示并重新询问
- **关键问题**: 这需要改动 `game_loop()` 的结构。当前 `game_loop()` 内部只有一个 `loop`。需要在外层嵌套第二个循环吗？还是将 `loop` 改造成"每局一个迭代"的结构？尝试两种方案并比较优劣。

**学习点**: 嵌套循环控制、`loop` 与 `while` 的选择。

### L2-3: 动态范围提示（二分搜索辅助）

记录用户的猜测历史，每次猜完后显示缩小的范围：

```
当前范围: 1-50
请输入你的猜测 (1-50): 25
📉 太小了！往上猜。
当前范围: 26-50       ← 新增
```

实现要点：
- 维护 `min_guess: u32` 和 `max_guess: u32` 两个变量
- 根据 `Ordering::Less` / `Ordering::Greater` 更新边界
- 在提示文本中动态显示范围
- **边界情况**: `(min..=max)` 在 `min > max` 时是空区间，但正常游戏中不应出现（为何？）

**学习点**: 状态管理、`Ordering` 模式匹配、闭区间语义。

### L2-4: 尝试次数分档优化

当前 `print_performance()` 有 5 个档位。添加一个"最优次数"概念：对于范围 [1, N]，二分查找最多需要 ceil(log2(N)) 次。在评价中加入：

```
（理论最优: 7 次, 你用了 3 次 — 比最优还少？你是不是知道了答案？）
```

如果用户次数少于理论下限（比如 1-100 范围一次就猜中，概率 1%），给出特殊评价。概率超过 50 则显示：

```
（完全随机猜的期望约 50 次）
```

**学习点**: 数学计算与 Rust 类型转换（`f64` vs `u32`）、`match` 守卫条件。

## Level 3: 设计思维（架构与扩展）

### L3-1: 模块化重构

当前所有代码在 `src/main.rs` 一个文件中。请设计重构方案，将代码拆分为以下模块：

```
src/
├── main.rs       # 入口点，仅调用 game_loop
├── game.rs       # game_loop() 核心逻辑
├── input.rs      # read_input(), parse_guess()
├── random.rs     # generate_secret()
├── output.rs     # print_welcome(), print_performance()
└── lib.rs        # 导出所有 pub 函数（如果需要）
```

- 那些函数需要标记为 `pub`？原来的 `fn` 变成什么可见性？
- 各模块之间的依赖关系是什么？（画出 import 图）
- `main.rs` 是否可以只保留 3 行代码？

**学习点**: Rust 模块系统、`mod` 与 `use`、可见性控制。

### L3-2: 实现"计算机猜数"模式（反向游戏）

用户在心里想一个 1-100 的数字，计算机用二分查找策略来猜。用户通过输入 `+`（太小）、`-`（太大）、`=`（正确）来反馈。

```
我想好了数字。
计算机: 是 50 吗？(+ 太小 / - 太大 / = 正确):
用户: +
计算机: 是 75 吗？(+ 太小 / - 太大 / = 正确):
用户: -
计算机: 是 62 吗？(+ 太小 / - 太大 / = 正确):
用户: =
计算机: 我用 3 次就猜到了！
```

实现要点：
- 二分查找算法实现
- 解析用户的 `+`/`-`/`=` 反馈
- 处理用户"作弊"情况（如输入矛盾：上一次说 50 太小，下一次说 40 太大）
- **提示**: 使用 `RangeInclusive<u32>` 或 `(min, max)` 元组跟踪搜索空间

**学习点**: 算法实现、`match` 字符串匹配、输入验证。

### L3-3: 排行榜系统

添加文件持久化排行榜：

```
排行榜:
1. Alice  2 次 (困难模式)  2026-06-05
2. Bob    4 次 (中等模式)  2026-06-04
3. Alice  5 次 (中等模式)  2026-06-03
```

设计要点：
- 磁盘存储格式设计（JSON? 纯文本? CSV?）
- 排行榜数据结构：按难度+尝试次数排序
- 文件名和路径：`~/.guessing_game/scores.json` 或 `./scores.txt`
- 去重策略：同一玩家多条记录如何处理？
- 使用 `serde` + `serde_json` 还是手写格式？
- **不要求完整实现**，但需要给出数据结构定义和关键函数签名

**学习点**: 序列化方案选择、文件 I/O、排序算法。

### L3-4: 配置系统

设计一个配置系统，允许用户通过命令行参数或配置文件自定义游戏行为：

```bash
cargo run -- --min 1 --max 200 --lang zh
```

或通过 `~/.guessing_game/config.toml`:

```toml
min = 1
max = 500
language = "en"
```

- 使用 `clap` 还是手写参数解析？
- 配置优先级：命令行参数 > 环境变量 > 配置文件 > 默认值
- 如何将配置传递给 `game_loop()`？构造一个 `GameConfig` 结构体？
- **不要求完整实现**，设计 `GameConfig` 结构体和 `fn parse_config() -> GameConfig` 签名即可

**学习点**: 配置管理、`clap` crate、`Default` trait。
