## Level 1：基础巩固

### 1-1：理解 `println!` 和 `vec!`

```rust
// println! 的展开大致为（简化）：
// println!("Hello {}!", name)
// → 编译期检查格式字符串参数数量，生成对 std::io::_print 的调用

// vec![1, 2, 3] 展开为：
// {
//     let mut v = Vec::new();
//     v.push(1); v.push(2); v.push(3);
//     v
// }
```

宏在编译期展开，不产生运行时开销。与 C `#define` 的区别：Rust 宏是语法层面的操作，不是文本替换。

---

### 1-2：编写简单声明宏

```rust
macro_rules! my_vec {
    () => { Vec::new() };
    ($($x:expr),+ $(,)?) => {{
        let mut v = Vec::new();
        $(v.push($x);)+
        v
    }};
}

// 用法
let v: Vec<i32> = my_vec![1, 2, 3];
let empty: Vec<String> = my_vec![];
```

---

### 1-3：宏 vs 函数

| 特性 | 宏 | 函数 |
|------|-----|------|
| 可变参数数量 | ✅ | ❌ |
| 编译期代码生成 | ✅ | ❌ |
| 类型检查 | 展开后进行 | 定义时 |
| 可读性/调试 | 较难 | 容易 |
| 选择原则 | 函数不够用才用宏 | 优先函数 |

## Level 2：组合应用

### 2-1：`my_map!` 宏

```rust
macro_rules! my_map {
    ($($key:expr => $value:expr),* $(,)?) => {{
        let mut map = std::collections::HashMap::new();
        $(map.insert($key, $value);)*
        map
    }};
}

let m = my_map!["a" => 1, "b" => 2];
```

---

### 2-2：调试宏

```rust
macro_rules! debug {
    ($($arg:tt)*) => {
        if std::env::var("DEBUG").is_ok() {
            eprintln!("[DEBUG] {}", format!($($arg)*));
        }
    };
}
debug!("x = {}, y = {}", 10, 20);
// 仅当环境变量 DEBUG 存在时输出
```

## Level 3：设计思考

### 3-1：何时用宏，何时用函数

**用宏**：
- 需要可变参数数量（`println!`, `vec!`）
- 需要编译期代码生成（`#[derive]`）
- 需要访问调用点信息（`file!()`, `line!()`）
- 减少大量重复的样板代码

**不用宏**：
- 可以用泛型函数实现 —— 泛型有更好的错误信息
- 增加了不可见的控制流
- 团队不熟悉宏语法

### 3-2：宏卫生性

Rust 声明宏（`macro_rules!`）是部分卫生的：宏内引入的局部变量不会与调用点冲突，但标识符可能冲突。使用 `$crate` 前缀引用 crate 内部路径避免命名冲突。

## 迁移思维练习

### C 宏与 Rust 宏

| 方面 | C `#define` | Rust `macro_rules!` |
|------|-----------|---------------------|
| 机制 | 预处理器文本替换 | 语法树级别的模式匹配 |
| 类型安全 | 无（文本替换） | 展开后类型检查 |
| 错误信息 | 难以定位（显示展开后代码） | 引用原始宏调用点 |
| 卫生性 | 不卫生（容易变量冲突） | 部分卫生 |
| 能力 | 简单替换 | 模式匹配、递归、重复 |

**迁移提示**：C 程序员习惯用宏补语言不足。Rust 中宏的适用场景更窄——泛型、trait 和枚举已经覆盖了大部分 C 中需要宏的场景。

---

*宏是 Rust 的"元编程"工具。学习曲线较陡，但在需要减少重复样板或操作编译期信息时不可替代。优先用函数和泛型解决问题，宏是最后的武器。*
