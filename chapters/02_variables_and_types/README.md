# 第 2 章：变量与类型 (Variables and Types)

## 本章目标

学完本章后，你将能够：

1. 理解 Rust 的变量绑定（Variable Binding）机制，以及"默认不可变"（Immutable by Default）的设计哲学
2. 掌握 `mut` 关键字的使用场景，能够区分"可变变量"和"不可变变量"
3. 理解变量遮蔽（Shadowing）的机制，并能区分 `mut` 和遮蔽的本质区别
4. 理解常量（Constant）的定义方式和使用限制
5. 熟练使用 Rust 的所有标量类型（Scalar Types）：整数、浮点数、布尔值、字符
6. 理解 `usize` 和 `isize` 的含义及其在不同架构下的行为
7. 使用元组（Tuple）进行多值聚合，掌握模式解构和索引访问两种方式
8. 使用数组（Array）存储固定长度的同类型数据
9. 使用 `as` 关键字进行显式类型转换
10. 理解类型推断（Type Inference）的工作原理，并在必要时进行显式类型标注（Type Annotation）

## 为什么需要学习这一章

如果你来自 Python 背景，这一章是 Rust 入门最重要的基础。Python 和 Rust 在"变量"这个看似简单的概念上有根本性的差异，理解这些差异决定了你能否平稳过渡到 Rust 的思维方式。

### Python 的变量：名称绑定

在 Python 中，变量名更像是一个"标签"（label），贴在对象上。你可以随时把同一个名称贴到不同类型的对象上：

```python
x = 42        # x 贴到 int 对象上
x = "hello"   # 现在 x 贴到 str 对象上，没有任何问题
```

Python 没有类型标注的要求（虽然有 type hint），也没有"变量本身不可变"的概念。你只能控制对象是否可变（如 list vs tuple），但不能阻止名称被重新绑定。

### Rust 的变量：所有权与类型绑定

在 Rust 中，`let` 创建的是"变量绑定"（Variable Binding）——名称与一块内存的所有权之间建立了绑定关系。这个绑定默认是不可变的（immutable），而且绑定一旦建立，其类型就固化了：

```rust
let x = 42;
// x = 43;  // 编译错误！默认不可变
// x = "hello"; // 编译错误！类型不匹配
```

这不是 Rust 的缺陷，而是一个深思熟虑的设计选择。默认不可变迫使你显式地思考"哪些数据会在程序执行过程中发生变化"，从而在编译期就能捕获大量潜在的逻辑错误。

### 本章在 Rust 学习路径中的位置

本章位于 Rust 从 Python 迁移的第一站。在了解了 Rust 的基本工具链（第 1 章）之后，你将正式开始编写 Rust 代码。变量和类型是一切程序的基础，后续的所有章节——所有权、结构体、枚举、模式匹配、泛型——都建立在本章的基础之上。

## 背景知识

### 1. 变量绑定（Variable Binding）

在许多编程语言中，"声明变量"和"赋值"是两个步骤。Rust 将这两步合并为"变量绑定"——使用 `let` 关键字同时声明名称并将值绑定到该名称上。

> 核心概念：Rust 中的变量绑定默认是不可变的。如果你尝试对不可变变量重新赋值，编译器会拒绝编译，并给出清晰的错误信息。

这个设计有几个好处：
- **安全性**：你可以信任一个值在绑定后不会被意外修改
- **并发友好**：不可变数据天然适合多线程共享
- **编译器优化**：不可变数据让编译器更容易做优化

### 2. 可变性（Mutability）

当你确定一个变量的值需要变化时，使用 `mut` 关键字：

```rust
let mut count = 0;
count += 1;  // 合法
```

注意：`mut` 允许改变值，但**不允许改变类型**。一个 `mut` 变量的类型在声明时就已确定，并保持不变。

### 3. 变量遮蔽（Variable Shadowing）

遮蔽是指用 `let` 重新声明一个同名的变量。新变量会"遮蔽"旧变量，后续代码使用新变量：

```rust
let x = 5;
let x = x + 1;    // 遮蔽，x = 6
let x = "hello";   // 再次遮蔽，x 现在是 &str 类型
```

遮蔽的本质是**创建一个全新的变量绑定**，旧值可能仍存在（如果所有权未转移），只是不再可以通过该名称访问。

遮蔽与 `mut` 的关键区别：
- `mut` 改变同一个绑定的值，类型必须一致
- 遮蔽创建新的绑定，类型可以完全不同
- 遮蔽后的变量依然是不可变的（除非再次使用 `let mut`）

### 4. 常量（Constants）

常量使用 `const` 关键字声明，与 `let` 绑定的变量有以下区别：

| 特性 | `let` 变量 | `const` 常量 |
|------|-----------|-------------|
| 类型标注 | 可推断 | 必须显式标注 |
| 作用域 | 任意作用域 | 任意作用域（包括全局） |
| 求值时机 | 运行时 | 编译期 |
| 可变性 | 可选 mut | 永不可变 |
| 命名惯例 | snake_case | SCREAMING_SNAKE_CASE |
| 表达式 | 运行时表达式 | 只能使用常量表达式 |

### 5. 标量类型（Scalar Types）

标量类型表示单一的值。Rust 有四种基本标量类型：

**整数类型**：按长度和有无符号分为 10 种。

| 长度 | 有符号 | 无符号 |
|------|--------|--------|
| 8 位 | `i8` | `u8` |
| 16 位 | `i16` | `u16` |
| 32 位 | `i32` | `u32` |
| 64 位 | `i64` | `u64` |
| 128 位 | `i128` | `u128` |
| 架构相关 | `isize` | `usize` |

`isize` 和 `usize` 的大小取决于目标机器的指针宽度：在 64 位架构上是 64 位，在 32 位架构上是 32 位。`usize` 在 Rust 中广泛用于数组索引和集合长度。

默认整数类型是 `i32`——这是 Rust 在性能和兼容性之间的平衡选择。

整数字面量支持多种进制：
- 十进制：`1_000_000`（下划线只是视觉分隔，不影响值）
- 十六进制：`0xff`
- 八进制：`0o77`
- 二进制：`0b1111_0000`
- 字节：`b'A'`（仅 u8）

**浮点类型**：`f32`（单精度）和 `f64`（双精度，默认）。

Rust 的浮点数遵循 IEEE 754 标准。默认浮点类型是 `f64`，因为在现代 CPU 上 `f64` 的速度与 `f32` 基本相同，但精度更高。

**布尔类型**：`bool`，只有两个值：`true` 和 `false`。布尔值占 1 个字节。

**字符类型**：`char`，占 4 个字节，表示一个 Unicode 标量值（scalar value），范围从 `U+0000` 到 `U+D7FF` 和 `U+E000` 到 `U+10FFFF`。

> 重要：Rust 的 `char` 不是 C 语言的 1 字节 `char`。它能存储任何合法的 Unicode 字符，包括中文、emoji 等。这与 Python 3 的单个字符字符串概念类似，但 Rust 的 `char` 始终是 4 字节的固定宽度。

### 6. 复合类型（Compound Types）

复合类型可以将多个值组合成一个类型。Rust 有两个原生的复合类型：

**元组（Tuple）**：固定长度的异构集合。

- 创建：`let tup: (i32, f64, char) = (500, 6.4, 'A');`
- 模式解构：`let (x, y, z) = tup;`
- 索引访问：`tup.0`, `tup.1`, `tup.2`（注意是 `.` 不是 `[]`）
- 单元元组（Unit Tuple）`()`：空元组，零大小类型（ZST），表示"没有值"

**数组（Array）**：固定长度的同构集合，分配在栈上。

- 类型签名：`[T; N]`，其中 T 是元素类型，N 是编译期常量
- 创建：`let arr: [i32; 5] = [1, 2, 3, 4, 5];`
- 批量初始化：`let zeros = [0; 100];`（100 个 0）
- 索引访问：`arr[0]`（运行时边界检查，越界会 panic）
- 安全访问：`arr.get(index)` 返回 `Option<&T>`

> 数组与 Vec 的区别：数组长度在编译期确定，分配在栈上；Vec（向量）长度可动态增长，数据分配在堆上。数组适合已知固定长度的场景（如月份名称），Vec 适合动态数据。

### 7. 类型推断（Type Inference）

Rust 编译器拥有强大的类型推断能力。大部分情况下，你不需要显式标注类型：

```rust
let x = 42;       // 推断为 i32（默认整数类型）
let y = 3.14;     // 推断为 f64（默认浮点类型）
let mut v = Vec::new();
v.push(1u8);      // 从 push 的实参推断 Vec<u8>
```

但在某些情况下必须显式标注（Type Annotation）：
- 函数签名中的参数和返回值
- 结构体和枚举的定义
- 静态变量和常量
- 类型无法推断时（如 `"42".parse()` 不知道目标类型）

### 8. 类型转换（Type Casting）

Rust 使用 `as` 关键字进行显式类型转换（type casting）：

```rust
let x: i32 = 300;
let y: u8 = x as u8;  // 可能截断，300 -> 44
let z: f64 = x as f64; // 安全扩展
```

注意：
- `as` 转换不保证值的完整性——超出目标范围的转换会截断
- 从浮点数到整数的转换会截断小数部分（向零舍入）
- 并非所有类型之间都可以 `as` 转换（如结构体之间不行）
- Rust 的 `as` 不做隐式转换，这避免了 C/C++ 中常见的隐式类型提升问题

## 代码讲解

### 第一部分：变量绑定（第 40-56 行）

```rust
let x = 5;
// x = 6;  // 取消注释会导致编译错误
```

`let` 创建变量绑定。与 Python 不同，Rust 的变量默认是不可变的。如果你试图给 `x` 重新赋值，编译器会拒绝编译。这是 Rust 安全哲学的基础——一个值在你不期望它变化的时候，它就不会变化。

当需要可变性时，使用 `mut` 关键字：

```rust
let mut counter = 0;
counter += 1;
counter += 1;
```

注意 Rust 没有 C/C++/Python 的 `++` 自增运算符，必须使用 `+= 1`。这是因为 Rust 的设计者认为 `++` 运算符的语义复杂（前置 vs 后置），不值得引入。

### 第二部分：遮蔽 vs mut（第 58-84 行）

遮蔽示例：

```rust
let value = 42i32;           // value 是 i32 类型
let value = "现在是字符串了";  // value 被遮蔽，现在是 &str 类型
```

这里的关键洞察是：**遮蔽创建了一个全新的变量绑定**，旧绑定被隐藏（但旧值遵循正常的生命周期规则）。这与 `mut` 完全不同——`mut` 改变的是同一个绑定的值，类型不能变。

为什么 Rust 同时提供了这两种机制？
- `mut`：适用于"计数器递增"这类值变化但类型不变的场景
- 遮蔽：适用于"数据转换管道"——你可以用同一个名称经历一系列转换，而不必想一堆中间变量名（如 `data`, `data_str`, `data_parsed` 等）

### 第三部分：常量（第 86-99 行）

```rust
const MAX_POINTS: u32 = 100_000;
```

常量在编译期求值，这意味着它们的值在程序运行前就已确定。这与 `let` 变量不同——`let` 绑定的值可以在运行时通过函数调用、用户输入等方式获取。

常量的类型必须显式标注（不能依赖类型推断），命名惯例是全大写加下划线（SCREAMING_SNAKE_CASE）。

### 第四部分：标量类型（第 101-160 行）

**整数类型**：Rust 提供了丰富的整数类型选择。从 Python 角度，这看起来过度繁杂——Python 只有一个 `int`，且可以任意扩展精度。但在系统编程中，精确控制内存布局是必要的：一个 `u8` 只占 1 字节，而 Python 的 `int` 在 CPython 中至少占用 28 字节（包括引用计数和类型信息）。

`isize` 和 `usize` 是特殊的"指针宽度"整数。`usize` 在 Rust 中无处不在——数组索引、`Vec::len()` 返回值、切片长度等都是 `usize`。在 64 位系统上，`usize` 和 `u64` 大小相同，但语义不同：`usize` 表示"大小或索引足够大"。

**浮点类型**：`f64` 是默认选择。在几乎所有现代 CPU 上，`f64` 的运算速度都不比 `f32` 慢，但精度更高。

**布尔类型**：只有 `true` 和 `false`，占 1 字节。注意 Rust 的 `bool` 不能自动转换为整数（与 C 不同）。

**字符类型**：`char` 占 4 字节，存储 Unicode 标量值。这是 Rust 与 C 的重大区别之一——C 的 `char` 只是 1 字节的 ASCII/扩展 ASCII，而 Rust 的 `char` 可以表示任何 Unicode 字符，包括 emoji。

### 第五部分：类型推断（第 162-180 行）

Rust 的编译器用 Hindley-Milner 类型的类型推断算法。在大部分情况下，你不需要写类型标注：

```rust
let x = 42;           // i32
let y = 3.14;         // f64
let mut v = Vec::new();
v.push(1u8);          // 推断为 Vec<u8>
```

但有些场景必须标注——最经典的例子是 `parse()` 方法：

```rust
let n: u32 = "42".parse().expect("解析失败");
```

如果不标注 `: u32`，编译器不知道你要解析成 `u32` 还是 `i32` 还是 `u64`……因为 `parse` 是一个泛型方法，其返回类型由调用上下文决定。

### 第六部分：元组（第 182-204 行）

元组是 Rust 中最简单的复合类型。它类似于 Python 的 tuple，但有重要区别：

- Rust 元组是**异构静态类型**——每个位置的类型在编译期确定
- 访问方式有模式解构和 `. 索引` 两种
- 元组的"索引"是 `.0`, `.1`, `.2`（用句点），与数组的 `[0]`（用方括号）完全不同

单元元组 `()` 是一个非常有趣的类型——它只包含一个值 `()`，在内存中占用 0 字节。它类似于 Python 的 `None` 或 `void` 函数返回值，但它是一个真正的类型和值，而非"无值"的占位符。

### 第七部分：数组（第 206-240 行）

Rust 数组的类型签名 `[T; N]` 中，N 必须是编译期常量。这意味着数组的长度在编译时就已确定，数组本身分配在栈上。

```rust
let arr: [i32; 5] = [10, 20, 30, 40, 50];
```

Rust 对数组索引做运行时边界检查（bounds checking）。如果索引超出范围，程序会**panic**（崩溃），而不是产生未定义行为（如 C）或抛出异常（如 Python）。当然，你也可以用 `arr.get(index)` 获得安全的 `Option` 返回值——这是 Rust 推荐的越界安全访问方式。

### 第八部分：类型转换（第 242-262 行）

Rust 使用 `as` 进行显式类型转换：

```rust
let x: i32 = 300;
let y: u8 = x as u8;  // 300 % 256 = 44，注意截断！
```

`as` 转换是"信任程序员"的操作——编译器不会阻止你进行可能损失信息的转换，但在运行时也不会做任何保护。这与 Rust 的"默认安全"哲学形成对比，反映出系统编程需要在安全和性能之间做权衡。

## 与 Python 的对照

### 1. 名称绑定 vs 变量绑定

**Python**：变量是对象的名称标签。同一个名称可以随时指向不同的对象（包括不同类型的对象）。

```python
x = 42        # x 绑定到 int 对象 42
x = "hello"   # x 绑定到 str 对象 "hello"，没问题
```

**Rust**：`let` 创建的是"名称到值的绑定"，这个绑定有固定的类型。

```rust
let x = 42;         // x: i32, 不可变
// x = "hello";     // 编译错误！类型不匹配
let x = "hello";    // 遮蔽：新的绑定，新的类型（旧绑定被隐藏）
```

### 2. 动态类型 vs 静态类型

**Python**：动态类型。类型检查在运行时进行。

```python
def add(a, b):
    return a + b

add(1, 2)      # 正常：3
add("a", "b")  # 正常："ab"（字符串拼接）
add(1, "a")    # 运行时 TypeError！
```

Python 3.5+ 引入了 type hint，但它们是**可选的、不做强制检查**：

```python
def add(a: int, b: int) -> int:
    return a + b

add(1, "a")  # 不会在运行时报错（但 IDE/mypy 会警告）
```

**Rust**：静态类型。类型检查在编译时进行，type error 永远是编译错误，不会出现在运行时。

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

// add(1, "a"); // 编译错误！永远到不了运行时
```

### 3. Python dict/tuple vs Rust Tuple

**Python**：

```python
# Python tuple
t = (1, "hello", 3.14)
a, b, c = t          # 解构
print(t[0])          # 索引访问：用方括号

# Python dict
d = {"name": "Alice", "age": 30}
```

**Rust**：

```rust
// Rust tuple
let t: (i32, &str, f64) = (1, "hello", 3.14);
let (a, b, c) = t;   // 模式解构
println!("{}", t.0); // 索引访问：用句点，不是方括号！

// Rust 没有内置 dict，有 HashMap（需要 use std::collections::HashMap）
```

### 4. Python list vs Rust Array

**Python list**：

```python
nums = [1, 2, 3, 4, 5]
nums.append(6)    # 动态增长
nums[0] = 100     # 可修改
len(nums)         # 运行时长度
```

Python 的 list 是动态数组，元素在堆上分配，可以增长、收缩，可以包含不同类型的元素。

**Rust Array**：

```rust
let nums: [i32; 5] = [1, 2, 3, 4, 5];
// nums.push(6);     // 编译错误！数组没有 push
// nums = [1, 2, 3]; // 编译错误！大小不匹配
let len = nums.len(); // 编译期可知
```

Rust 的数组是固定长度的栈分配容器。如果你需要类似 Python list 的动态数组，应该使用 `Vec<T>`：

```rust
let mut nums: Vec<i32> = vec![1, 2, 3, 4, 5];
nums.push(6);       // 现在可以了
```

### 5. Python str vs Rust char

**Python**：字符串是 Unicode 序列，没有"字符"类型。单个字符就是一个长度为 1 的字符串。

```python
c = 'A'       # 长度为 1 的 str
emoji = '🦀'  # 长度为 1 的 str（但内部可能占多个字节）
```

**Rust**：`char` 是占 4 字节的 Unicode 标量值。`String` 和 `&str` 是 UTF-8 编码的字节序列。

```rust
let c: char = 'A';       // 4 字节
let emoji: char = '🦀';  // 4 字节，一个 Unicode 标量值
let s: &str = "Hello";   // 字符串切片，UTF-8 字节序列
```

> 重要：在 Rust 中，字符串索引不能用 `s[0]`，因为 UTF-8 编码下单个"字符"可能占多个字节。`s[0]` 在 Rust 中不会编译通过——你需要使用 `s.chars().nth(0)` 来获取第 0 个 Unicode 字符。

### 6. Python None vs Rust Unit Tuple

**Python**：`None` 是 `NoneType` 的单例值，表示"没有值"或"空"。

```python
def noop():
    pass           # 隐式返回 None

result = noop()    # result 是 None
```

**Rust**：`()` 是 unit type（单元类型），也叫 unit tuple。它是零大小类型（Zero-Sized Type, ZST）。

```rust
fn noop() {
    // 隐式返回 ()
}

let result: () = noop(); // result 是 ()，占 0 字节
```

区别在于：`()` 是一个实际的类型和值（虽然占 0 字节），而 Python 的 `None` 是一个特殊的单例对象。在泛型编程中，`()` 经常用作"不需要值"的占位符（如 `Result<(), Error>` 表示只关心错误）。

### 7. 类型转换差异

**Python**：类型转换通过构造函数完成，是隐式的对象创建。

```python
x = 42
y = float(x)      # 42.0
z = str(x)        # "42"
w = int("42")     # 42，解析字符串
```

Python 的类型转换本质上是创建新对象——`int`, `float`, `str` 等都是类构造函数。

**Rust**：类型转换通过 `as` 关键字或 `From`/`Into` trait 完成。

```rust
let x: i32 = 42;
let y = x as f64;              // as: 简单类型转换（会截断）
let z = x.to_string();         // ToString trait：数字到字符串
let w: i32 = "42".parse().unwrap(); // FromStr trait：字符串解析
```

Rust 没有隐式类型转换——你必须显式转换。这避免了"隐式转换导致精度丢失"或"意想不到的类型提升"等问题。

## 常见错误

### 错误 1：忘记 `mut`

```rust
let x = 5;
x = 6; // error[E0384]: cannot assign twice to immutable variable `x`
```

**解决方案**：如果变量需要重新赋值，使用 `let mut x = 5;`。Rust 编译器给出的错误信息通常非常清晰，包含了修改建议。

### 错误 2：类型不匹配

```rust
let mut x = 5;
x = "hello"; // error[E0308]: mismatched types
```

**解决方案**：`mut` 不能改变变量类型。如果你需要改变类型，使用遮蔽：`let x = "hello";`

### 错误 3：数组越界

```rust
let arr = [1, 2, 3];
let x = arr[5]; // 运行时 panic: index out of bounds
```

**解决方案**：使用 `arr.get(5)` 返回 `Option`，在编译时无法确定索引是否合法时推荐使用。如果索引确实是常量，检查它是否小于数组长度。

### 错误 4：遮蔽混淆

```rust
let x = 5;
{
    let x = "hello"; // 在内层作用域遮蔽
    println!("{}", x); // "hello"
}
println!("{}", x); // 5 —— 外层的 x 未被修改！
```

这不是错误，但很多人会困惑。关键在于理解：**遮蔽创建的是新绑定，不修改旧绑定**。在内层作用域结束后，内层的 `x` 离开作用域，外层的 `x` 重新可见。

### 错误 5：`char` 只能表示一个 Unicode 标量值

```rust
let c: char = 'ab'; // error[E0762]: character literal may only contain one codepoint
```

`char` 只能表示一个 Unicode 标量值（scalar value），不能表示多个字符或字素簇（grapheme cluster）。如果你需要多个字符，使用 `&str` 或 `String`。

### 错误 6：整数溢出

在 debug 模式下，整数运算溢出会导致 panic：

```rust
let x: u8 = 255;
let y = x + 1; // debug 模式：panic；release 模式：回绕到 0
```

**解决方案**：使用 `wrapping_*` 系列方法（如 `x.wrapping_add(1)`）或 `checked_*` 方法（返回 `Option`）来明确处理溢出行为。

## 本章小结

- Rust 的变量绑定使用 `let`，默认不可变。这是 Rust 安全哲学的基石。
- 使用 `mut` 关键字可以创建可变变量，但类型不能改变。
- 遮蔽（shadowing）使用 `let` 重新声明同名变量，可以改变类型，本质上是创建新绑定。
- 常量使用 `const`，必须标注类型，在编译期求值。
- Rust 有丰富的标量类型：整数（10 种）、浮点数（2 种）、布尔、字符（4 字节 Unicode）。
- `usize` 和 `isize` 的大小与目标架构的指针宽度相同。
- 复合类型包括元组（异构、固定长度）、数组（同构、固定长度、栈分配）。
- 类型推断强大但并非万能，函数签名、常量等必须显式标注。
- 类型转换使用 `as` 关键字，不做隐式转换。
- 数组索引有运行时边界检查，越界会 panic。使用 `get()` 进行安全访问。
